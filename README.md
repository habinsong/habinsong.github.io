# Habin Song Photographs — 사용 설명서

내 사진(디지털/필름)과 글을 보여주는 개인 사이트입니다. 서버 없이 **GitHub Pages**에서 무료로 돌아가고, 글은 이 저장소 안의 파일로 관리합니다. 이 문서 하나로 처음 설정부터 글 발행까지 전부 따라 할 수 있습니다.

## 한눈에 보는 흐름

```
[처음 한 번]  GitHub에 올리고 Pages 켜기
[글 쓸 때마다] 로컬 서버 켜기 → /admin/에서 글 쓰기 → ZIP 내려받기
              → ZIP을 이 폴더에 풀기 → python3 scripts/release.py → git push (Actions가 배포)
```

---

## 1. 준비물

- **Python 3** — macOS에는 기본 설치되어 있습니다. 터미널에서 `python3 --version`으로 확인.
- **git** 그리고 **GitHub 계정**
- 브라우저 (Chrome/Safari/Edge/Firefox 최신 버전)

---

## 2. 처음 한 번: 인터넷에 올리기

터미널에서 이 폴더로 이동한 뒤:

```bash
cd ~/habinsong
git init
git add -A
git commit -m "첫 커밋"
```

GitHub(github.com)에서 `<내아이디>.github.io` 이름으로 저장소를 만들고 연결해 올립니다:

```bash
git remote add origin https://github.com/<내아이디>/<내아이디>.github.io.git
git push -u origin master
```

그다음 저장소 페이지에서 **Settings → Pages → Source: GitHub Actions** 를 선택하세요. 푸시할 때마다 [.github/workflows/pages.yml](.github/workflows/pages.yml)이 `release.py`를 돌려 `_release/`를 만들고 그것만 배포합니다. 몇 분 뒤 `https://<내아이디>.github.io/` 주소가 생깁니다.

> 저장소에는 원본이 올라가지만 공개되는 것은 `_release/` 안의 파일뿐입니다. README, DESIGN, `scripts/`는 사이트 주소로 열리지 않습니다.

> 주소가 나오면 [site.json](site.json)의 `"baseUrl"`이 그 주소로 되어 있는지 확인하세요. 이 값이 있어야 RSS 피드(feed.xml)와 sitemap.xml이 만들어집니다. 다른 사이트의 sitemap도 robots.txt에 함께 알리려면 `"sitemaps"` 배열에 주소를 넣으면 됩니다.

---

## 3. 내 컴퓨터에서 미리 보기

파일을 더블클릭해서 열면 동작하지 않습니다(브라우저 보안 때문). 꼭 로컬 서버로 여세요:

```bash
cd ~/habinsong
python3 -m http.server 8000
```

- 사이트: <http://localhost:8000>
- 글쓰기(관리자): <http://localhost:8000/admin/>

끌 때는 터미널에서 `Ctrl+C`.

---

## 4. 글 쓰기

`http://localhost:8000/admin/` 에서 씁니다. 화면은 왼쪽 **작성 영역**, 오른쪽 **미리보기**로 나뉩니다.

### 4-1. 글 정보

| 항목 | 설명 |
|------|------|
| 제목 | 글 제목. 파일 이름(id)도 여기서 자동으로 만들어집니다 (한글 OK) |
| 날짜 | 글 날짜. 목록·아카이브 정렬에 쓰입니다 |
| 상태 | **게시** = 사이트에 보임 / **초안** = 숨김 |
| 시리즈 (선택) | 연작 이름 (예: "제주 2026"). 같은 이름을 쓰면 같은 시리즈로 묶입니다 |
| 태그 | 쉼표로 구분 (예: `film, seoul`) |
| 요약 | 글 목록에 표시될 한두 문장 |

### 4-2. 사진 넣기

**사진** 영역에 이미지 파일을 끌어다 놓거나 파일 선택 버튼을 누르세요. 사진마다:

- **연도·세부 정보**(카메라·렌즈·조리개·셔터·ISO)는 사진의 EXIF에서 **자동으로 채워집니다**. 필름 스캔처럼 EXIF가 없으면 직접 쓰면 됩니다.
- **비율**도 실제 픽셀 크기로 자동 측정됩니다.
- **대체 텍스트(alt)** 는 꼭 채워 주세요 — 스크린리더와 검색엔진용 사진 설명입니다.
- **매체**(디지털/필름)와 **톤**(컬러/흑백)은 갤러리 필터에 쓰입니다.
- **본문에 삽입** 버튼으로 커서 위치에 넣고, **삭제**로 뺍니다.

넣은 사진은 브라우저 안(IndexedDB)에 저장되므로 **새로고침해도 사라지지 않습니다.**

### 4-3. 본문 쓰기 (캔버스)

캔버스를 클릭하고 그냥 쓰면 됩니다. 워드처럼요.

- **Enter** = 새 문단
- 툴바 **본문 / 소제목 / 인용** = 커서가 있는 문단의 모양 바꾸기
- 툴바 **사진** = 파일 고르면 커서 자리에 사진이 들어감 (캔버스에 파일을 바로 끌어다 놓아도 됨)
- 사진 아래 **코멘트** 칸 = 그 사진에 붙는 짧은 이야기
- **사진 전체 추가** = 올린 사진 전부를 한 번에 본문으로
- **갤러리** = 여러 사진을 격자 하나로 묶기 (체크박스로 고름)
- **링크** = 참고 링크 목록. 한 줄에 하나, `이름 | https://주소` 형식
- 사진/갤러리/링크 블록의 **↑ ↓ ×** = 순서 이동·삭제
- 붙여넣기 하면 서식은 버려지고 글자만 들어갑니다 (의도된 동작)

쓰는 내용은 **자동 저장**됩니다(우측 상단에 저장 시각 표시). 같은 브라우저에서 다시 열면 이어서 쓸 수 있습니다.

## 5. 게시하기

1. 관리자 화면 아래 **ZIP 내려받기** 클릭 (빠진 항목이 있으면 알려줍니다)
2. 내려받은 ZIP을 **이 폴더(저장소 루트)에 풀기** — 글 JSON과 사진이 제자리에 들어갑니다
3. 터미널에서:

```bash
cd ~/habinsong
python3 scripts/release.py
git add -A
git commit -m "새 글: 제목"
git push
```

푸시하면 GitHub Actions가 같은 스크립트를 다시 돌려 배포합니다. 로컬에서 `release.py`를 먼저 돌리는 이유는 ZIP을 병합하고, 잘못된 값이 있으면 올리기 전에 알기 위해서입니다.

`release.py`가 알아서 다 합니다: ZIP에 담긴 목록 파일(`*.merge.json`)을 `photos.json` / `series.json` / `content/posts/index.json`에 **자동 병합**하고(같은 id면 갱신), 빠진 파일·잘못된 값이 없는지 **검증**한 뒤, 배포본 `_release/`를 만듭니다. 에러가 나면 어디가 문제인지 알려주고 멈추므로, 깨진 상태로 올라갈 일이 없습니다.

push 후 1~2분이면 사이트에 반영됩니다.

---

## 6. 기존 글 고치기

1. 관리자에서 **JSON 불러오기** 클릭 → `content/posts/글이름.json` 선택
2. 제목·본문·코멘트·순서를 고칩니다. 사진은 저장소에 이미 있으므로 **원본 파일이 없어도 됩니다**
3. 다시 **ZIP 내려받기** → 5번 절차 그대로 (같은 id라서 기존 글이 갱신됩니다)

## 7. 글 내리기

`content/posts/index.json`에서 해당 글의 `"status"`를 `"published"` → `"draft"`로 바꾸고 `release.py` 실행 후 push. 다시 올리려면 반대로.

## 8. 시리즈

같은 시리즈 이름으로 쓴 글들은 사이트의 **시리즈** 섹션에 묶여 나옵니다. 시리즈 설명을 붙이고 싶으면 [series.json](series.json)에서 해당 항목에 `"description"`을 추가하세요:

```json
{ "id": "제주-2026", "title": "제주 2026", "description": "한 주 동안의 제주." }
```

## 9. 언어

사이트는 한국어/영어/일본어/중국어를 지원합니다. 방문자 브라우저 언어로 자동 선택되고, 최상단에서 바꿀 수 있으며 선택이 기억됩니다. `?lang=ja` 처럼 주소로 강제할 수도 있습니다. **글 본문은 쓴 언어 그대로** 나옵니다(UI만 번역됨).

## 10. 폴더 구조

```
habinsong/
├── index.html, *.js, *.css   ← 공개 사이트
├── admin/                    ← 글쓰기 도구 (로컬에서만 사용)
├── photos/                   ← 사진 파일 (글 id별 폴더)
├── content/posts/            ← 글 JSON + 목록(index.json)
├── photos.json               ← 갤러리에 보일 사진 목록
├── series.json               ← 시리즈 목록
├── site.json                 ← 사이트 설정 (제목·이메일·baseUrl)
├── scripts/release.py        ← 병합·검증·빌드 스크립트
└── _release/                 ← 스크립트가 만드는 배포본 (직접 수정 금지, 저장소에는 올라가지 않음)
```

## 11. 문제가 생겼을 때

| 증상 | 해결 |
|------|------|
| 고쳤는데 화면이 그대로 | 브라우저 캐시입니다. **Cmd+Shift+R** (강력 새로고침) |
| 관리자 페이지가 하얗게 나옴 | 파일을 더블클릭으로 열었을 가능성 → 3번처럼 로컬 서버로 여세요 |
| `release-error: ...` | 메시지가 가리키는 파일/항목을 고치면 됩니다 (예: 사진 파일 누락, alt 비어 있음) |
| 다른 브라우저에 초안이 없음 | 초안·사진은 브라우저별 저장입니다. 쓰던 브라우저에서 이어 쓰세요 |
| 사진을 잘못 올림 | 사진 패널의 **삭제** 버튼 (본문에 넣은 것도 같이 빠짐) |
| 전부 새로 시작하고 싶음 | **초안 초기화** 버튼 (저장된 사진 포함 전부 삭제) |

## 12. 보안 메모

- 이 사이트는 서버·데이터베이스·로그인 없이 정적 파일만 서빙합니다 — 공격면 자체가 작습니다.
- 모든 페이지에 **CSP**(콘텐츠 보안 정책)가 걸려 있어 외부 스크립트 실행이 차단됩니다. 외부 라이브러리/CDN 의존성도 0개입니다.
- 글 렌더링은 전부 텍스트 노드로 처리되어 HTML 주입(XSS)이 통하지 않고, 링크는 http(s)만 허용됩니다.
- `release.py`는 경로 탈출(`../`)과 잘못된 데이터를 거부합니다.
- `/admin/`은 배포되어도 **보기 전용 도구일 뿐**입니다 — 서버에 쓸 수 있는 권한이 없어 남이 열어도 내 사이트를 바꿀 수 없습니다. 검색엔진에는 노출되지 않게 처리되어 있습니다(noindex + robots).
- 보안 제보 연락처는 `/.well-known/security.txt`로 게시됩니다.
- GitHub Pages는 응답 헤더를 지원하지 않아 CSP를 meta 태그로 적용합니다. 이 방식은 클릭재킹 방지(frame-ancestors) 같은 헤더 전용 보호는 못 하는데, 필요해지면 Cloudflare를 앞에 두는 방법이 있습니다.
